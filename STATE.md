## Как мы работаем (важно для нового чата)
- Разработчик новичок, пишет по-русски, просит КОРОТКИЕ ответы.
- Код выдавать ФАЙЛАМИ (zip с папками в нужной структуре), разработчик копирует их через Проводник.
  В чате писать только: что создано/изменено, как поставить, чек-лист.
- Файлы всегда полные, без «...». Комментарии в коде на русском, имена переменных на английском.
- Команды терминала по одной, с пояснением, где вводить (ОС Windows, PowerShell, терминал VS Code в папке anime-rater).
- Новые библиотеки и бэкенд разрешены (SPEC v2), но только если это реально проще: перед добавлением назвать, объяснить зачем, спросить согласие.
- Модель данных и структуру папок молча не менять.
- STATE.md обновлять в конце каждого этапа (отдавать файлом).
- Перед кодом этапа: список файлов и не больше 3 вопросов.
- Claude не запускает код: возможны ошибки, их присылают текстом, Claude сначала объясняет причину, потом даёт полные исправленные файлы.
- Для правок интерфейса: скриншот + фраза «хочу так». Для правок логики: «как сейчас» + «как должно быть». Claude называет нужные файлы, их присылают.
- Крупные идеи делаем отдельными этапами, а не вместе с мелкими правками.

## Формат файла экспорта (версия 1)
JSON: `{ app: 'anime-rater', version: 1, exportedAt, anime[], tags[], tiers[], ratingHints[] }`.
В anime поле image — строка data:image/...;base64 или null, остальные поля как в модели.
Если изменится модель Anime: поднять BACKUP_VERSION в backup.ts и сохранить чтение старых файлов.
Импорт «заменить» сохраняет id из файла. Импорт «добавить» пересчитывает id: метки и тиры объединяются по названию
(без учёта регистра), аниме с уже существующим названием пропускаются, непустые описания оценок не перезаписываются.
Очистка возвращает тиры S–D и описания по умолчанию (константа DEFAULT_TIERS продублирована в backup.ts и db.ts).

## Схема БД (Dexie, версия 2)
- anime: `++id, title, rating, tierId, isReference, createdAt, updatedAt, *tagIds`
- tags: `++id, name`
- tiers: `++id, order`
- ratingHints: `score` (первичный ключ — оценка 1–10)
Любое следующее изменение схемы = `db.version(3)...`, старые версии не удалять.
boolean (isReference) нельзя искать через `.where()`, поэтому эталоны выбираются через `.filter()` / в памяти.

## Принятые решения
- Тема: класс `dark` на `<html>`, пары классов `bg-white dark:bg-slate-900`. По умолчанию тёмная. Хранится в localStorage (ключ anime-rater-theme).
- Роутер: HashRouter (адреса /#/tierlist) — для GitHub Pages. Фильтр по оценке: `/#/?rating=N`.
- BASE в vite.config.ts = '/anime-rater/' (должно совпадать с именем репозитория).
- Данные локальные, привязаны к адресу сайта (включая порт): localhost:5173, localhost:5174 и сайт на GitHub Pages — РАЗНЫЕ базы.
  Перенос между устройствами и адресами — только через экспорт/импорт.
- Форма: AnimeFormPage → (EditLoader) → AnimeForm; при редактировании грузится один раз.
- Dexie: `new Dexie(...) as Dexie & { таблицы }`.
- Стиль эталона только в `src/lib/styles.ts` + `ReferenceBadge`.
- Картинки: Blob (JPEG, макс. 600px), показ через useObjectUrl.
- Фильтр по меткам: режим «И». Поиск без учёта регистра. Эталон нельзя сохранить без оценки.
- Тир-лист: MouseSensor (6px) и TouchSensor (200 мс, допуск 8px), pointerWithin, DragOverlay, justDragged,
  палитра TIER_COLORS, удаление тира → аниме в «Без тира», сортировка внутри тира по оценке.
- Калибровка: блок N показывает эталоны с оценкой РОВНО N. Эталоны с дробной оценкой не показываются, вверху предупреждение.
- Философия оценок: аниме оценивается ЦЕЛИКОМ, по общему ощущению (вайбу). Оценки только целые 1–10 (поле rating — number).
- Оформление «хаб», ЧЁРНО-БЕЛОЕ (этап A, версия 6). Цветов нет: шкала slate и «акцентная» шкала indigo (имя оставлено намеренно) обе серые. Выбранные кнопки: чёрное на светлой теме, белое на тёмной (CHIP_BASE / CHIP_SELECTED / CHIP_UNSELECTED в formStyles.ts). Утилиты в index.css: frame (толстая рамка, толщина [--fw:..], цвет [--fr:..]), hub-block (ровный тёмный блок с размытыми краями, без узора; класс dark на блоке даёт светлый текст внутри), hub-bg (тот же фон для заглушки картинки).
- Шрифт один: IBM Plex Mono (Google Fonts, index.html), html 15px, БЕЗ ЗАГЛАВНЫХ БУКВ. Пиксельный шрифт и цветочный узор УДАЛЕНЫ полностью. Логотип обычный текст (Layout.tsx). Офлайн в PWA Plex заменится системным моноширинным.
- Кнопки: основная чёрная/белая, вторичная с тонкой рамкой, «опасная» (удаление, очистка) чёрная с чёрной рамкой. Красный остался только у текстов ошибок валидации. Переключатели (Toggle.tsx) = квадратик + подпись. Вид списка и режим тир-листа переключаются подчёркнутыми словами.
- Эталон: звёздочка рядом с оценкой (RatingMark.tsx) плюс самая тёмная (в тёмной теме светлая) рамка карточки (styles.ts). Плашки «Эталон» нет. В форме аниме эталон = переключатель «Эталон» со звёздочкой.
- Шапка (ПК): логотип по центру, НЕ ссылка; меню текстом по центру; на телефоне нижняя панель.
- Главная: два вида списка (Мелко / Список), выбор в localStorage ('anime-rater-view'), по умолчанию «Мелко».
- Заглушка без картинки (AnimeImage): тёмный фон и крупная первая буква названия.
- Этап B (тип и жанры): у аниме поле kind (AnimeKind | null, подписи в lib/animeKinds.ts), фильтр по типу на главной и в тир-листе (ИЛИ), отдельно от меток. Импорт Шикимори дописывает тип и жанры (метки), у уже имеющихся без типа тоже. Лимит Шикимори 90 запросов в минуту (пауза 700 мс). Не проверено на живом Шикимори.
- Этап C (тир-лист): два режима (localStorage 'anime-rater-tier-mode', по умолчанию «По оценкам»). «По оценкам» (RatingTierList.tsx): строки 10…1 и «Без оценки», аниме встают сами по оценке (дробные округляются вниз), серый градиент от белого (10) к чёрному (1), перетаскивания нет, тап открывает форму. «Свой тир-лист» (CustomTierList.tsx): прежние тиры и перетаскивание плюс кнопки «Заполнить по оценкам» (заменяет тиры на 10…1 и ставит аниме по оценкам), «Сбросить» (все аниме в «Без тира», тиры остаются), «Раскладки» (LayoutsDialog.tsx: сохранить текущий тир-лист под названием, загрузить, удалить). Действия в db/layoutActions.ts. Фильтры по типу и меткам работают в обоих режимах.
- Схема Dexie версия 4: новая таблица layouts ('++id, createdAt'; запись Layout: name, createdAt, tiers [{name,color}], assignments [[id аниме, номер тира]]). В upgrade стандартные тиры S/A/B/C/D со старыми разноцветными цветами перекрашены в серые (если цвет меняли сами, не трогаются). Тиры по умолчанию (db.ts populate, backup.ts DEFAULT_TIERS): серые. BACKUP_VERSION = 3: в файл добавлены layouts, файлы версий 1 и 2 читаются. При импорте «Добавить» раскладки с тем же названием пропускаются, id аниме в раскладках пересчитываются.
- Эмодзи и символы убраны, вместо них текст или SVG (Doodles.tsx: StarIcon, CrossIcon).
- Не менялись: TagPicker.tsx, tierActions.ts.
- Палитра цветов нового тира (tierColors.ts): приглушённые ретро-оттенки + чёрный/серый/светлый. Старые тиры сохраняют прежние цвета.
- Навигация без иконок, активный пункт — линия чёрная (в тёмной теме белая).
- Шикимори (проверено руками в этапе 6):
  - Сайт переехал на домен shikimori.io (shikimori.one перенаправляет, и редирект ломает запросы из браузера). Адрес хранится в константе SHIKIMORI_SITE.
  - Список `GET /api/users/{ник}/anime_rates?is_nickname=1&status=completed` отдаётся браузеру напрямую (CORS разрешён), вход не нужен, если список открыт в приватности.
  - Лимит Шикимори: 5 запросов в секунду, 90 в минуту. API отдаёт на 1 запись больше limit — дубли убираются по id аниме.
  - Картинки Шикимори браузеру НЕ отдаёт (CORS), поэтому нужен посредник. Выбран Cloudflare Worker (бесплатный тариф, карта не нужна). Он пропускает только ваш сайт (список ALLOWED_ORIGINS) и только картинки /system/animes/ с Шикимори.
  - Без VPN Шикимори может не открываться (таймаут): импорт тогда выдаёт понятную ошибку.

## Заметки по окружению
- PowerShell: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`.
- Сервер: `npm run dev` в терминале VS Code в папке anime-rater. Адрес вида http://localhost:5173/anime-rater/ (порт может быть другим, если 5173 занят старым сервером).
- С VPN localhost может не открываться (http://127.0.0.1:5173/anime-rater/).
- Посмотреть/сбросить базу: F12 → Application → IndexedDB → anime-rater.
- Проверка на телефоне до выкладки: `npm run dev -- --host`, адрес Network (одна Wi-Fi сеть).
- Проверка сборки и PWA: `npm run build`, затем `npm run preview`.
- Обновление сайта после правок: `git add .`, `git commit -m "что изменил"`, `git push`.
- iPhone: установленное с домашнего экрана приложение и вкладка Safari могут иметь РАЗНЫЕ базы: импортировать данные в установленном приложении.
- Cloudflare Worker: dash.cloudflare.com → Workers & Pages. Код лежит в cloudflare-worker/worker.js; после правок его надо заново вставить в Cloudflare и нажать Deploy (git push его не обновляет).
