## Как мы работаем (важно для нового чата)
- Разработчик новичок, пишет по-русски, просит КОРОТКИЕ ответы.
- Код выдавать ФАЙЛАМИ (zip с папками в нужной структуре), разработчик копирует их через Проводник.
  В чате писать только: что создано/изменено, как поставить, чек-лист.
- Файлы всегда полные, без «...». Комментарии в коде на русском, имена переменных на английском.
- Команды терминала по одной, с пояснением, где вводить (ОС Windows, PowerShell, терминал VS Code в папке anime-rater).
- Без лишних библиотек сверх SPEC.md, без бэкенда.
- Модель данных и структуру папок молча не менять.
- STATE.md обновлять в конце каждого этапа (отдавать файлом).
- Перед кодом этапа: список файлов и не больше 3 вопросов.
- Claude не запускает код: возможны ошибки, их присылают текстом, Claude сначала объясняет причину, потом даёт полные исправленные файлы.
- Для правок интерфейса: скриншот + фраза «хочу так». Для правок логики: «как сейчас» + «как должно быть». Claude называет нужные файлы, их присылают.
- Крупные идеи делаем отдельными этапами, а не вместе с мелкими правками.

## Формат файла экспорта (версия 1)
JSON: `{ app: 'anime-rater', version: 1, exportedAt, anime[], tags[], tiers[], ratingHints[] }`.
В anime поле image — строка data:image/...;base64 или null, остальные поля как в модели.
Если изменится модель Anime: поднять BACKUP_VERSION в backup.ts и сохранить чтение старых файлов.
Импорт «заменить» сохраняет id из файла. Импорт «добавить» пересчитывает id: метки и тиры объединяются по названию
(без учёта регистра), аниме с уже существующим названием пропускаются, непустые описания оценок не перезаписываются.
Очистка возвращает тиры S–D и описания по умолчанию (константа DEFAULT_TIERS продублирована в backup.ts и db.ts).

## Схема БД (Dexie, версия 2)
- anime: `++id, title, rating, tierId, isReference, createdAt, updatedAt, *tagIds`
- tags: `++id, name`
- tiers: `++id, order`
- ratingHints: `score` (первичный ключ — оценка 1–10)
Любое следующее изменение схемы = `db.version(3)...`, старые версии не удалять.
boolean (isReference) нельзя искать через `.where()`, поэтому эталоны выбираются через `.filter()` / в памяти.

## Принятые решения
- Тема: класс `dark` на `<html>`, пары классов `bg-white dark:bg-slate-900`. По умолчанию тёмная. Хранится в localStorage (ключ anime-rater-theme).
- Роутер: HashRouter (адреса /#/tierlist) — для GitHub Pages. Фильтр по оценке: `/#/?rating=N`.
- BASE в vite.config.ts = '/anime-rater/' (должно совпадать с именем репозитория).
- Данные локальные, привязаны к адресу сайта (включая порт): localhost:5173, localhost:5174 и сайт на GitHub Pages — РАЗНЫЕ базы.
  Перенос между устройствами и адресами — только через экспорт/импорт.
- Форма: AnimeFormPage → (EditLoader) → AnimeForm; при редактировании грузится один раз.
- Dexie: `new Dexie(...) as Dexie & { таблицы }`.
- Стиль эталона только в `src/lib/styles.ts` + `ReferenceBadge`.
- Картинки: Blob (JPEG, макс. 600px), показ через useObjectUrl.
- Фильтр по меткам: режим «И». Поиск без учёта регистра. Эталон нельзя сохранить без оценки.
- Тир-лист: MouseSensor (6px) и TouchSensor (200 мс, допуск 8px), pointerWithin, DragOverlay, justDragged,
  палитра TIER_COLORS, удаление тира → аниме в «Без тира», сортировка внутри тира по оценке.
- Калибровка: блок N показывает эталоны с оценкой РОВНО N. Эталоны с дробной оценкой не показываются, вверху предупреждение.
- Философия оценок: аниме оценивается ЦЕЛИКОМ, по общему ощущению (вайбу). Оценки только целые 1–10 (поле rating — number).
- Оформление: переопределены цвета slate (бумага/чернила), indigo (оранжевый акцент), скругления, serif для h1/h2 — всё в @theme в index.css.
- Навигация без иконок, активный пункт — оранжевая линия.

## Заметки по окружению
- PowerShell: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`.
- Сервер: `npm run dev` в терминале VS Code в папке anime-rater. Адрес вида http://localhost:5173/anime-rater/ (порт может быть другим, если 5173 занят старым сервером).
- С VPN localhost может не открываться (http://127.0.0.1:5173/anime-rater/).
- Посмотреть/сбросить базу: F12 → Application → IndexedDB → anime-rater.
- Проверка на телефоне до выкладки: `npm run dev -- --host`, адрес Network (одна Wi-Fi сеть).
- Проверка сборки и PWA: `npm run build`, затем `npm run preview`.
- Обновление сайта после правок: `git add .`, `git commit -m "что изменил"`, `git push`.
- iPhone: установленное с домашнего экрана приложение и вкладка Safari могут иметь РАЗНЫЕ базы: импортировать данные в установленном приложении.
